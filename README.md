# sakuya

QUIC transport implementation for Open Gensokyo Network, administratively supported by Starspun Works.

The repository is at an early stage. It holds parts of a QUIC version 1 implementation and does not yet provide a usable connection. The APIs are experimental and are not stable production APIs.

## Layout

- `crates/sakuya_wire`: wire-level value types (variable-length integers and fields that keep the width of their encoding, connection IDs and their lengths, stateless reset tokens, stream IDs, stream counts, packet numbers and the length of their field, versions, error codes), version-independent packet header interpretation and the headers a sender writes up to the Packet Number field, the cutting of a datagram into its packets (protected packets, and the Retry and Version Negotiation packets that are not), the encryption levels with the frame types that can appear in each, QUIC version 1 frames and transport parameters. The crate root holds what every QUIC version shares, the frame sets that compose the frames of version 1 with those of extensions, and the sets of parameters keyed by ID that compose parameter types in the same way; everything else of RFC 9000 is in its `v1` module. Each transport parameter is a type of its own, and the transport parameters of an endpoint are a slot for each type of the parts it uses, with the parameters no type claims kept as unknown ones. The DATAGRAM frame of RFC 9221 and the RESET_STREAM_AT frame of the reliable stream reset draft are extensions, each with its transport parameter in a module behind a feature of the same name (`datagram`, `reset_stream_at`), off by default; a frame set without an extension reads its Frame Types as unknown, and transport parameters without it keep its parameter as an unknown one. Every wire format is read and written as `nitori_call` operations, which also run synchronously on byte slices and `Bytes`; payload fields are chunks of the source, without copying. A frame value states every detail of its encoding (the width of each variable-length integer, which optional fields are present, the raw fields of ACK), so reading a frame and writing it again reproduces its bytes; the Frame Type must use its shortest encoding.
- `crates/sakuya_packet_protection`: packet protection primitives from RFC 9001: Initial secrets, key derivation, header protection, AEAD packet protection, truncation of packet numbers in the Packet Number field and the Retry integrity tag, behind a cryptographic backend trait with a `ring` implementation (the default `ring` feature). It depends on `sakuya_wire` for the connection IDs and packet numbers it takes.
- `crates/sakuya_clock`: the `MonotonicClock` trait, the monotonic clock and timer that a connection's driver reads and sleeps on and whose instants links report, and checked addition for its instants.
- `crates/sakuya_clock_tokio`: `TokioClock`, the `MonotonicClock` of a tokio runtime: tokio's time as standard library instants, and tokio's timer.
- `crates/sakuya_link`: the `Link` trait, a channel that sends and receives whole datagrams between this side and one peer and tells when it has ended; the link binding traits by which a transport gives links, taking new ones as peers appear (`AcceptingLinkBinding`) or setting one up to a given peer (`ConnectingLinkBinding`); and the identity of a link (`LinkId`): its two ends, in types the link chooses, and an identity unique within a process that tells apart links with the same two ends.
- `crates/sakuya_udp_tokio`: UDP over a tokio runtime, on Linux: `UdpBinding`, a socket that takes links from new peers and sets up links to given ones, and `UdpLink`, one peer from one local address. The socket does not fragment and ignores the path MTU the kernel learns, reads and marks ECN, takes IPv4 on an IPv6 socket bound to the unspecified address, and batches with GSO and GRO. Whichever receive or accept of a binding holds the reader's turn reads the socket for all of them, with the turn handed on when it is done or dropped; a dropped receive loses no datagram. Datagrams that cannot be replied to (from port 0, or to a broadcast or multicast address) make no link, the links not yet accepted share one bound on the datagrams they hold, and the socket stops using GSO or ECN only once a send without it has gone through. Socket calls go through `nix`, and the path MTU discovery option through `rustix`.
- `crates/sakuya_datagram_routing`: routing of received UDP datagrams to registered deliverers (a shared-bucket index keyed by connection ID or, for zero-length connection IDs, by this side's end of the link, registrations revoked by RAII handles, frozen candidate groups, non-inline reflow of unclaimed datagrams, re-examination and publication of new Initial receivers, and a hook for stateless reset detection), and the claim mechanism by which several candidates compete for one datagram.
- `crates/sakuya_stream`: per-stream send and receive components. The send direction has connection-level credit reservation and commitment, a send buffer contract with an implementation keyed by stream offset, and a stream sender with its flow-control and termination policies; the receive direction has a receive buffer contract with a fragment-map implementation, connection-level receive accounting, and a stream receiver with reads, local stop requests and policy-driven delivery boundaries. The stream sender is generic over the reset target it commits and the stream receiver over the reset facts it keeps: by default both take the resets of RFC 9000, and the `reset_stream_at` feature, off by default, adds a module of the same name with the reliable stream reset draft (RESET_STREAM_AT) for both directions: the reset target, requests and frames of a sender that can end a stream with RESET_STREAM_AT, which take a value that exists only for a peer that advertised the extension, and the reset facts and frame methods of a receiver that takes it. Both directions are synchronous cores; waiting and async adapters are not implemented.
- `crates/sakuya_tls`: the TLS 1.3 handshake layer for QUIC. It has the TLS code points (cipher suites with their hash and AEAD, extension types, handshake types, alert descriptions, protocol versions), the handshake messages (ClientHello, ServerHello and HelloRetryRequest, EncryptedExtensions, CertificateRequest, Certificate with X.509 certificates or a raw public key, CertificateVerify, Finished, NewSessionTicket, and the message_hash message of the transcript) with their extensions, and the collection of one whole handshake message from the bytes of an encryption level, under a limit for each message type. Messages are read from the bytes of one whole message as `nitori_call` operations, with variable-length fields as chunks of those bytes, and written back byte for byte; a recognized extension in a message that may not carry it is rejected, unknown extensions are kept, and every read failure names the TLS alert it calls for. The transcript and key schedule form one chain of values that move, with the role of a server or a client as a type parameter: each step consumes the one before, so the Handshake traffic secrets need the ServerHello, the 1-RTT secrets need the server's Finished, and a client reads the server's Finished only after the server has authenticated with a certificate or with the PSK it accepted. The chain derives the traffic secrets for packet protection, the Finished messages, PSK binders, 0-RTT secrets, the exporter and the PSKs of tickets, over a backend with the capabilities of `nitori_crypto`. The handshake engines of a server and of a client run in steps, given by a trait for each role that the engine's start state implements: each step takes the state before it by value and returns the traffic secrets or the completion of the handshake, with its exporter, together with the state of the next step. The states own the backend and the role's capabilities; a step reads and writes the CRYPTO bytes of the current encryption level through one access the connection lends on every poll and asks the connection for transport parameters through synchronous methods, and each step is also a `nitori_call` operation for every implementation of the trait; a server holds back the client's 1-RTT secret until it has verified the client's Finished, and admits 0-RTT only when the handshake, the connection and its ticket policy all agree. The engines do not yet open encrypted ClientHello layers or authenticate clients with certificates, and there is no QUIC client connection yet to drive the client engine.
- `crates/sakuya_recovery`: loss recovery, congestion control and datagram size probing for a link path, from RFC 9002 and RFC 9000 §14. It has the replaceable parts as traits (the RTT estimate, the congestion controller, the pacer, what to do when the probe timeout expires, the ECN marking, datagram size probing, and the factory that makes them for each link path and lends their congestion access), the implementations it provides (the RTT estimate of RFC 9002, NewReno with a token bucket pacer, and binary search probing with black hole detection), and the rules no implementation may change as functions (the probe timeout, the loss thresholds, persistent congestion, the acknowledgment delay taken off a sample). It reads no clock and does not depend on the connection's tree; `sakuya_connection` does not use it yet.
- `crates/sakuya_connection`: the structure a QUIC connection is composed in. A connection is one future that drives the calls of a tree of nodes: the connection, its logical link entries and logical paths, the link paths of each logical path, and the established layer and recovery layers that come and go. A composition is a list of parts and a type of choices; each part has, in each layer, data components and kinds of calls. The driver wakes exactly the calls whose wakers were called, folding the wakes between two polls into one wake of its own waker; it lends each call its node's data and that of the nodes above, by type and without overlaps, records what was taken mutably, rereads the deadlines and the reactions of the components that read it until nothing changes, applies requests to build, end or move nodes at once, and runs the expiries that are due after the calls. The parts of QUIC version 1 are not composed in it yet.
- `verification/wire-differential`: differential tests of `sakuya_wire` and `sakuya_packet_protection` against quinn-proto, s2n-quic-core and rustls, robustness tests, and fuzz targets for frames, transport parameters, packet headers, packet protection and the handshake messages of `sakuya_tls`. It is not a member of the workspace, has its own dependencies, and no package of the workspace depends on it; see its README.

Byte IO, the call mechanism, process-unique identities and cryptographic capabilities come from [nitori](https://github.com/opengensokyonet/nitori).

## Development

Install [rustup](https://rustup.rs/). The repository pins `nightly-2026-11-03` with rustfmt and Clippy in `rust-toolchain.toml`; run commands from the repository root so rustup selects this toolchain. Nightly language features are required. Packages remain unpublished (`publish = false`).

`nitori_call`, `nitori_crypto`, `nitori_id` and `nitori_io` are Git dependencies on [nitori](https://github.com/opengensokyonet/nitori), and `snafu` is a Git dependency, each pinned to a specific commit in `Cargo.toml`; Cargo fetches them automatically. The tests of `sakuya_tls` also use `nitori_crypto_aws_lc`, which builds aws-lc-rs from C sources and needs a C compiler and CMake.

From the repository root:

```sh
cargo fmt --all --check
cargo clippy --locked --workspace --all-targets -- -D warnings
cargo clippy --locked --workspace --all-targets --all-features -- -D warnings
cargo test --locked --workspace --all-targets
cargo test --locked --workspace --all-targets --all-features
cargo test --locked --workspace --doc
```

For development against local checkouts of nitori or SNAFU, an ignored `.cargo/config.toml` may patch their Git sources to local paths under `[patch."https://github.com/opengensokyonet/nitori"]` and `[patch."https://github.com/opengensokyonet/snafu"]`. Keep that configuration and the resulting lockfile changes out of commits; the committed lockfile records the public sources.
